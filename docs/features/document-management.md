# 文档管理与文件传输

在服务端内部，目录和文档都是目录树中的**结点**。文档并不直接指向物理文件，而是通过[修订版本](revisions.md)引用物理文件；同一个物理文件又可能同时被多个修订版本、用户头像或扩展所引用。

## 名称空间

同一目录内处于活动状态的文档和目录共用一个名称空间。例如，当目录中已经存在名为 `计划` 的目录时，不能再在该目录内创建名为 `计划` 的文档。此约束由数据库强制执行，也适用于并发发生的创建、移动、重命名和恢复操作。

项目被标记为删除后会释放其名称，因此可以创建同名的新项目。之后若要恢复原项目，必须为它指定不冲突的新名称或将其恢复到其他目录。

!!! note
    旧版本配置项 `document.allow_name_duplicate` 已被废弃且会被忽略，不能再用于允许重名。

## 删除、恢复与永久清除

常规删除会将文档或目录标记为已删除，而不是立即移除全部数据库记录和物理文件。持有 `list_deleted_items` 权限且能够读取目标目录的用户，可以分页查看该目录中已删除的直接子项目；持有 `restore` 权限的用户可以恢复项目，并在恢复时选择新的名称或父目录。

恢复一个目录时，服务端会检查整个待恢复子树的名称冲突。若目标父目录本身仍处于删除状态，应先恢复该父目录。永久清除则要求项目已经被标记为删除，并要求操作者持有 `purge` 权限和相应的对象访问权。

删除目录时，服务端会分别检查子树内各项目的权限。若只有部分项目可以删除，服务端将删除可操作的部分，并返回 `207` 及相应的项目标识符；永久清除目录则要求整棵子树都可被操作，不会以部分成功方式执行。

## 文件引用与传输取消

删除文档、修订版本或目录时，服务端会检查所涉及的物理文件是否仍可由其他活动文档、用户头像或扩展所拥有的非级联外键访问。只有当一个文件失去最后一个活动引用时，服务端才会取消它的待处理或正在进行的传输任务，并在数据库事务成功后安排物理文件清理。

因此，在文件去重后删除其中一份文档，不会错误中断仍被其他文档引用的文件传输。进入锁定模式是例外：所有尚未完成的文件传输任务都会被取消，而不论任务对应的用户是否具有锁定模式豁免权。

## 文件传输任务的状态

上传和下载都需要先取得文件传输任务。任务以不可并发重复认领的状态机管理：

| 状态 | 说明 |
|---|---|
| `pending` | 等待客户端开始传输，或在连接中断后等待恢复。 |
| `in_progress` | 已由一条传输连接认领，其他连接不能同时使用。 |
| `completed` | 传输及其最终数据库状态变更均已完成。 |
| `cancelled` | 因文件失去活动引用或服务端进入锁定模式而被撤销。 |
| `expired` | 开始期限或传输硬性期限已经届满。 |

被取消或已过期的任务不会重新回到可用状态。客户端收到包含 `data.task_status` 的 `410` 响应后，应丢弃对应的任务凭据；上传任务已被其他连接认领时，服务端返回 `409` 和 `in_progress` 状态。

### 上传期限

新上传任务最初的结束时间是开始传输的期限。客户端首次成功认领任务后，服务端会重新记录开始时间，并将结束时间改为传输的硬性期限。默认情况下，客户端有一小时开始上传，开始后有二十四小时完成上传；传输期间连续五分钟未收到数据帧时，本次连接会因空闲而中止。

连接中断或发生空闲超时后，只要硬性期限尚未届满，可恢复的任务就会回到 `pending`。服务端会在启动时执行一次废弃上传清理，并在收到后续上传请求时按配置的间隔执行有界的机会式清理。若某个新文档从未形成活动修订版本，清理会永久移除这个空壳文档并释放其名称；若废弃的是后续修订版本，则只移除该不活跃修订版本并修复当前修订版本指向。

同一创建者默认最多保留 16 个空白且尚未开始上传的文档。重复调用文档上传准备请求不会刷新期限，而会复用已有的待处理任务。

## 分块协商与断点续传

首次传输时，服务端从客户端声明的最大分块大小、`server.file_chunk_size` 和传输方向的硬性上限中选择最小值。上传方向允许的最小值为 512 字节，硬性上限为 64 KiB；下载方向允许的范围为 16 KiB 至 2 MiB。协商结果会记录在文件任务中，之后恢复同一任务时不会因配置变化而改变。

非空上传在提供有效 SHA-256 摘要时可以续传。服务端会记录文件大小、摘要和完整分块的检查点；客户端恢复时必须继续使用相同的文件元数据和不小于原协商值的最大分块大小。若确实需要舍弃进度，可以显式请求重新开始。未提供摘要的上传仍受支持，但连接中断后会从零开始。

本地存储会恢复到最后一个完整协议分块。S3 存储使用多部分上传并持久记录服务端实际确认的 Part Number 和 ETag；中断时尚未提交的一个 S3 分片尾部可能需要重新上传。使用 S3 时，应授予创建、上传、列出分片、完成和中止多部分上传所需的权限，并建议配置自动清理过期未完成多部分上传的生命周期规则。

下载可以从下一个尚未持久保存的完整分块的字节偏移量恢复，偏移量必须与任务记录的分块大小对齐。若客户端已经取得全部加密分块而仅错过了最终密钥，也可以使用等于文件大小的偏移量重新取得传输末尾信息。

下载期间，每个文件分块使用同一任务的 AES-GCM 密钥和不同的随机数分别加密。服务端在全部分块传输结束后才发送密钥；客户端完成解密和校验后需回复 `complete`，服务端随后才会把任务标记为已完成。若连接在确认前断开，任务仍可在期限内安全恢复。

## 上传校验与文件去重

上传完成时，服务端会校验实际文件大小；客户端提供了 SHA-256 摘要时，还会校验文件摘要。只有校验通过后，物理文件和对应修订版本才会被激活。

对于带有有效 SHA-256 摘要的非空上传，始终启用的 `builtin` 扩展会创建一个持久化去重任务。客户端的上传成功响应不等待实际合并完成；后台工作线程会选择创建时间和标识符排序最早的活动文件作为规范副本，先迁移数据库引用，再移除冗余的存储对象。

去重工作使用数据库租约，可以在进程意外退出后恢复，并会对可重试故障执行有界指数退避。已经开始的下载会继续使用原文件，待处理的下载则会改为引用规范副本。升级后不会自动扫描并去重历史文件。

## 搜索与分页

搜索功能需要全局 `search` 权限。查询会对文档和目录名称执行不区分大小写的字面量部分匹配；`%`、`_`、斜杠和引号等字符都按普通字符处理，而不是 SQL 通配符或语法。仅由空白构成的查询会被拒绝。

搜索结果还会依据用户对每个项目的读取权限进行过滤，且权限过滤发生在分页之前。可以选择只搜索文档或目录，并按名称、创建时间、大小或最后修改时间排序。没有活动修订版本的文档不会出现在结果中。

搜索、目录列表、已删除项目列表、修订版本列表以及多种管理列表都使用不透明游标分页，默认和最大页大小均为 128。下一页请求必须原样复用服务端返回的游标，并保持查询条件和排序方式不变；客户端不应尝试解码、修改或依赖游标内部格式。
