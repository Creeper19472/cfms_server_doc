# 锁定模式

在多种情况下，例如当系统管理员认为有充分证据证明一场数据泄露事件正发生或即将发生时，可以令服务端进入锁定模式。该模式将阻止任何用户绝大多数的请求尝试，除非这些用户具有锁定模式的豁免权，或请求访问的功能作为维持服务端最低限度运转的要件而被默认放行。

在进入锁定模式时，可以指定启用锁定模式的理由。

当启用锁定模式时，服务端将立刻取消所有尚在有效期内而未完成的文件传输任务，此举的效果将在文件下载功能上得到显著体现：在全部已加密的文件分块传输完成后，服务端将再次检查传输任务的当前状态，若任务已经取消，则拒绝下发密钥，故客户端虽拥有加密后的数据，却无法据此得到明文。此举旨在最大限度地实现对访问的即时控制。

!!! note
    所有尚在有效期内而未完成的文件传输任务都将在启用锁定模式时被取消，无论创建它们的用户是否拥有锁定模式的豁免权。

在启用和禁用锁定模式时，服务端都会向客户端发送一次事件广播，以通知客户端采取适当的措施。

锁定模式是**持久的**，不会因服务端的意外退出或重新启动而自行解除。
