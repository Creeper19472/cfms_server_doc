# 身份验证与安全管理

服务端把账户凭据保护、重复验证尝试的节流、来源网段封禁和全局应急锁定作为彼此独立的控制层。它们可以同时生效；例如，解除某个账户的身份验证锁定并不会绕过仍然有效的 IP 网段封禁。

## 密码与二步验证

用户密码使用 Argon2id 处理，并在散列前附加部署实例的 `security.pepper`。可以配置密码长度、正则表达式规则、需满足的最少规则数、强制定期过期，以及登录时强制修改不再符合当前策略的密码。

用户可以启用基于 TOTP 的二步验证。设置流程会生成共享密钥和备用代码，在完成验证码确认前仍可取消；备用代码在服务端同样经过 Argon2id 和 pepper 处理。持有 `manage_2fa` 权限的管理员可以查询或禁用其他用户的二步验证，系统管理员也可在无法通过常规接口恢复账户时使用维护命令清除 TOTP 状态。

!!! warning
    `security.pepper` 并非普通可轮换配置。丢失或替换它会使已有密码及 TOTP 备用代码无法按原方式验证。应将它与数据库备份一并保护，且不要将其记录在普通日志或提交到代码仓库。

## 身份验证节流

启用 `security.auth_throttle` 后，服务端分别维护以下失败状态：

- **账户**：超过阈值后施加逐步增加且具有上限的延迟；
- **账户与 IP 的组合**：在滚动窗口内达到阈值后锁定指定组合；
- **IP 地址**：在滚动窗口内出现大量失败后锁定该来源。

密码和 TOTP 验证流程均受这些控制约束。一次访问可能同时命中多个作用域，只有将所有匹配的活动锁定都解除后才能恢复验证。

持有 `list_auth_lockouts` 权限的管理员可以按作用域、用户名、IP 地址和验证因子精确筛选活动锁定。持有 `unlock_auth_lockouts` 权限的管理员可以在一个事务中解除至多 100 个精确指定的锁定；解除操作是幂等的，并会清除相应的失败历史。管理员提供的理由和实际结果会写入审计日志。

## IP 网段封禁

持有 `list_banned_subnets` 权限的管理员可以分页查看计划中、生效中或已过期的 CIDR 封禁规则。持有 `manage_banned_subnets` 权限的管理员可以创建、更新和删除规则；新安装实例中的 `sysop` 组默认拥有这两项权限。

封禁网段会被规范化。例如，`192.0.2.7/24` 将按 `192.0.2.0/24` 保存。规则的生效区间为 `[starts_at, expires_at)`：开始时间包含在内，结束时间不包含在内；开始时间默认是当前时间，结束时间可以为空而永久有效。

更新规则时可以调整理由、开始时间和结束时间，但不能直接改变 CIDR；需要改变网段时，应删除旧规则并创建新规则。若创建或更新的未过期规则会包含操作者自身的有效来源 IP，客户端必须显式确认自我封禁，以降低管理员意外切断自身访问的风险。

服务端启动时会将网段规则载入安全守卫，并通过事件机制同步运行中的更新。位于可信反向代理之后时，实际参与判断的是依据 `server.trusted_proxy_networks` 解析得到的客户端地址。

## 请求重放保护与 mTLS

常规已认证请求使用时间戳和随机数抵御短时间内的重复提交。请求时间戳允许的最大偏差为 15 秒，随机数字符串不得短于 16 个字符。客户端应为每个请求生成新的随机数，并确保系统时钟可靠同步。

启用 `security.require_client_cert` 后，TLS 握手会要求客户端出示证书，并依据 `security.client_cert_ca_path` 所指向的 OpenSSL 哈希目录进行验证。服务端要求 TLS 1.3；mTLS 只验证客户端证书是否受信任，并不替代 CFMS 自身的账户认证和对象授权。

## OpenID Connect 单点登录 {#openid-connect}

可选的 `oidc_sso` 扩展提供 OpenID Connect 登录起始和回调请求。扩展使用配置中的 Issuer、客户端凭据和固定回调 URI；客户端不能在请求中覆盖 `redirect_uri`。外部身份通过指定声明映射到 CFMS 用户名，并可选择在本地账户不存在时自动创建账户并加入预设用户组。

OIDC 依赖需通过 `uv sync --extra ext_oidc_sso` 安装，并在 `extensions.enabled` 中加入 `oidc_sso`。旧配置项 `sso.oidc.enabled` 已不再控制启用状态，可以通过[配置范本同步命令](../maintenance.md#sync-config-template)迁移。

## 自动暴力破解锁定

可选的 `brute_force_lockdown` 扩展会在滚动窗口内统计针对**已有账户**的本地密码或 TOTP 验证失败。只有失败总数达到阈值，且不同账户数或不同 IP 数至少有一项达到相应阈值时，才会触发[锁定模式](lockdown.md)。

成功登录、要求继续提供二步验证码的中间响应、已被节流的请求、未知用户名和 OIDC 请求都不会计入自动锁定。扩展不会覆盖已有的手动锁定理由，也不会自动解除锁定；管理员手动解除后会开始一个新的检测窗口。公开理由只包含配置的通用描述，具体触发计数和阈值则记录在 `automatic_lockdown` 审计条目中，而不会写出账户或 IP 列表。
